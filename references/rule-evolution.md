# 规则演化

## 规则来源

每条硬规则必须能够追溯到以下至少一项：

- 明确目标；
- 高成本边界；
- 已发生的结构性失败；
- 法律、安全、数据或兼容性要求；
- 可重复的验收证据。

## 规则状态

- `candidate`：候选想法，尚未验证。
- `experiment`：正在小范围测试。
- `default`：多数场景有效，但允许覆盖。
- `constraint`：高成本风险下的硬约束。
- `stale`：保护对象消失或证据过期。

## 升级为硬约束前

1. 指出它保护什么目标或边界。
2. 给出真实失败或风险证据。
3. 检查是否有更轻量的替代。
4. 评估是否限制无关场景。
5. 设计复审日期或失效条件。

## 删除规则前

验证保护对象是否仍存在；如果证据不确定，先降级为默认策略或实验，不直接删除高风险防线。
